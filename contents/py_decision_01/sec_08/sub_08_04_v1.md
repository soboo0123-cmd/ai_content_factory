# 8.4 교호진행의 반복게임 (v1 초안)

## 1. 도입
우리는 앞서 경기자들이 동시에 선택을 내리는 '동시 진행 게임(Simultaneous Game)'에 대해 배웠습니다. 하지만 현실의 많은 의사결정은 한 사람이 먼저 수를 두면, 상대방이 그 수를 보고 다음 수를 두는 방식으로 진행됩니다. 이를 **교호진행(Alternating Moves) 또는 순차 게임(Sequential Game)**이라고 합니다.

단순히 한 번의 순차 게임으로 끝나는 것이 아니라, 이러한 과정이 여러 회차에 걸쳐 반복될 때 경기자들의 전략은 어떻게 달라질까요? 이번 섹션에서는 **교호진행의 반복게임**이 갖는 특성과 이를 분석하는 핵심 도구인 '역진 귀납법(Backward Induction)', 그리고 파이썬을 활용한 시뮬레이션 방법을 학습합니다.

### 학습 목표
1. 순차 게임과 반복 게임의 결합 원리를 이해합니다.
2. 전개형 게임(Extensive Form Game)의 구조를 파악합니다.
3. 역진 귀납법을 통해 부분게임 완전 균형(Subgame Perfect Equilibrium)을 도출합니다.
4. 파이썬으로 반복되는 순차 게임의 로직을 구현합니다.

## 2. 본론

### 2.1 교호진행 게임의 구조: 전개형(Extensive Form)
교호진행 게임은 주로 '게임 트리(Game Tree)'라고 불리는 **전개형**으로 표현됩니다. 각 지점(Node)은 의사결정을 내리는 순간을 의미하며, 가지(Branch)는 선택 가능한 대안을 의미합니다.

- **뿌리 마디(Root Node):** 게임이 시작되는 지점입니다.
- **의사결정 마디(Decision Node):** 특정 경기자가 선택을 하는 지점입니다.
- **종착 마디(Terminal Node):** 게임이 종료되고 보수가 결정되는 지점입니다.

`[시각화: A가 먼저 선택(L/R)하고, B가 그에 따라 선택(u/d)하는 트리 구조 다이어그램]`

### 2.2 반복의 힘: 유한 반복과 무한 반복
순차 게임이 반복될 때, 경기자들은 '미래의 보상'을 고려하게 됩니다.

1.  **유한 반복(Finitely Repeated):** 게임이 끝나는 시점이 정해져 있는 경우입니다. 이론적으로는 마지막 회차부터 거꾸로 계산하면 첫 회차에서도 협력보다는 배반이 일어날 가능성이 큽니다.
2.  **무한 반복(Infinitely Repeated):** 언제 끝날지 모르는 경우입니다. 이때는 '미래의 보상'이 현재의 선택에 큰 영향을 미치며, 보복이나 보상 전략을 통해 협력이 유지될 수 있습니다.

### 2.3 핵심 원리: 역진 귀납법 (Backward Induction)
반복되는 교호진행 게임을 해결하는 가장 강력한 논리는 **역진 귀납법**입니다. 이는 "마지막 단계에서 경기자가 어떤 선택을 할지 알 수 있다면, 그 앞 단계의 경기자는 그 결과를 예측하여 최선의 선택을 할 수 있다"는 원리입니다.

$T$ 시점에서의 최적 선택 $\rightarrow T-1$ 시점에서의 최적 선택 $\rightarrow ... \rightarrow$ 현재의 최적 선택

이 과정을 통해 도출된 균형을 **부분게임 완전 균형(Subgame Perfect Equilibrium)**이라고 부릅니다.

### 2.4 파이썬 코드 예제: 반복되는 '신뢰 게임'
단순한 형태의 순차 게임인 '신뢰 게임(Trust Game)'이 2회 반복되는 상황을 파이썬으로 시뮬레이션해 보겠습니다.

- **경기자 A:** 먼저 B에게 투자할지(Invest) 말지(Exit) 결정합니다.
- **경기자 B:** A가 투자했다면, 수익을 나누어 가질지(Share) 혼자 가질지(Grab) 결정합니다.

```python
class SequentialGame:
    def __init__(self, rounds=2):
        self.rounds = rounds
        self.history = []

    def player_a_strategy(self, current_round, prev_b_move):
        # A의 전략: 이전 라운드에서 B가 배신했다면 투자하지 않음 (징벌 전략)
        if current_round > 1 and prev_b_move == 'Grab':
            return 'Exit'
        return 'Invest'

    def player_b_strategy(self, a_move):
        # B의 전략: 이기적인 경기자라면 항상 'Grab'을 선택 (역진 귀납법의 결과)
        if a_move == 'Invest':
            return 'Grab'
        return 'None'

    def play(self):
        prev_b_move = None
        total_payoff_a = 0
        total_payoff_b = 0

        for r in range(1, self.rounds + 1):
            print(f"--- Round {r} ---")
            move_a = self.player_a_strategy(r, prev_b_move)
            
            if move_a == 'Invest':
                move_b = self.player_b_strategy(move_a)
                if move_b == 'Share':
                    payoff = (2, 2) # 협력 시 보수
                else:
                    payoff = (0, 4) # B가 배신 시 보수
                prev_b_move = move_b
            else:
                move_b = 'None'
                payoff = (1, 1) # A가 거부 시 보수
                prev_b_move = move_b

            total_payoff_a += payoff[0]
            total_payoff_b += payoff[1]
            print(f"A's Move: {move_a}, B's Move: {move_b} -> Payoff: {payoff}")

        print(f"\nFinal Score - A: {total_payoff_a}, B: {total_payoff_b}")

# 게임 실행
game = SequentialGame(rounds=2)
game.play()
```

### 2.5 코드 설명 및 해석
1.  **전략의 연쇄:** 위 코드에서 `player_b_strategy`는 항상 자신에게 유리한 'Grab'을 선택합니다. 
2.  **A의 예측:** `player_a_strategy`는 이전 라운드 결과를 보고 판단하지만, 만약 B가 항상 'Grab'을 할 것을 미리 안다면(역진 귀납법), 첫 라운드부터 'Exit'을 선택하는 것이 합리적입니다.
3.  **반복의 영향:** `rounds`를 늘리고 B의 전략에 '평판(Reputation)' 개념을 넣으면(예: 나중에 더 큰 이익을 위해 초반엔 Share 선택), 결과는 완전히 달라질 수 있습니다.

`[시각화: 라운드 수 증가에 따른 A의 투자율 변화 그래프]`

## 3. 요약
- **교호진행 게임**은 순차적으로 수가 오가는 게임이며, 전개형(트리 구조)으로 분석합니다.
- **역진 귀납법**은 미래의 결과를 바탕으로 현재의 최적 행동을 결정하는 핵심 알고리즘입니다.
- **반복 게임**에서는 현재의 선택이 미래의 상대방 대응에 영향을 미치므로, 단기적 이익과 장기적 관계(평판, 보복) 사이의 균형이 중요합니다.
- 파이썬을 이용하면 복잡한 가지치기(Pruning)와 반복적인 의사결정 로직을 체계적으로 시뮬레이션할 수 있습니다.
