# 7.3.1 Decision Tree의 한계 예 (v2)

## 1. 도입
결정 트리(Decision Tree)는 데이터의 특성을 직관적인 '예/아니오' 질문으로 분류하는 매우 강력한 모델입니다. 하지만 모델이 학습하는 방식의 근본적인 특성 때문에 특정 상황에서는 매우 비효율적이거나 예측 능력이 급격히 떨어지는 모습을 보입니다. 

이번 절에서는 결정 트리가 가진 기하학적 제약과 구조적 불안정성을 구체적인 예를 통해 살펴봅니다. 이를 통해 왜 우리가 이후에 배울 '앙상블(Ensemble)' 기법을 필요로 하는지 그 이유를 명확히 이해하는 것을 목표로 합니다.

---

## 2. 본론

### 2.1 축에 수직인 분할의 한계 (Geometric Rigidity)
결정 트리의 가장 큰 특징은 한 번에 하나의 특성(Feature)만을 선택하여 분할한다는 점입니다. 이로 인해 결정 경계(Decision Boundary)는 항상 특성 축에 수직인 직선(또는 초평면)의 형태를 띠게 됩니다.

#### [시각화: 대각선 데이터셋과 결정 트리의 계단식 경계]
> - **왼쪽 그림:** $y = x$ 형태의 대각선으로 구분된 두 클래스 데이터.
> - **오른쪽 그림:** 이를 분류하기 위해 결정 트리가 만드는 '계단 모양(Staircase)'의 복잡한 경계선.
> - **슬라이더:** 트리의 깊이(Depth)를 조절함에 따라 계단이 더 촘촘해지지만, 결코 매끄러운 대각선이 되지 못하는 모습 시각화.

이러한 특성 때문에 데이터가 대각선 방향으로 분포되어 있다면, 결정 트리는 이를 표현하기 위해 수많은 분할을 반복해야 합니다. 

**예시:**
만약 데이터가 $x_1 > x_2$인 경우 클래스 A, 그렇지 않은 경우 클래스 B라고 가정해 봅시다. 
- 선형 모델(Linear Model)이라면 $x_1 - x_2 > 0$이라는 단순한 식으로 완벽하게 분류합니다.
- 결정 트리는 이를 표현하기 위해 $x_1 > 0.5$, 그 다음 $x_2 < 0.3$, 다시 $x_1 > 0.6 \dots$ 와 같이 수많은 '계단식' 질문을 던져야 합니다. 이는 모델을 불필요하게 복잡하게 만들고 일반화 성능을 떨어뜨립니다.

---

### 2.2 높은 분산과 구조적 불안정성 (Instability)
결정 트리는 '탐욕적 알고리즘(Greedy Algorithm)'을 사용합니다. 현재 단계에서 불순도(Impurity)를 가장 많이 낮추는 최적의 분할을 선택하지만, 이 선택이 전체 트리의 안정성을 해칠 수 있습니다.

특히, **데이터의 작은 변화가 트리의 뿌리(Root)부터 완전히 다른 구조를 만들게 되는 문제**가 발생합니다.

- **원인:** 최상단 노드에서 분할 기준이 되는 특성이 미세한 데이터 차이로 인해 바뀌면, 그 아래에 붙는 모든 자식 노드들의 질문 내용이 통째로 바뀝니다.
- **결과:** 동일한 데이터셋에서 샘플 몇 개만 제거하거나 추가해도 모델의 예측 논리 자체가 완전히 달라지는 '높은 분산(High Variance)' 문제를 겪게 됩니다.

---

### 2.3 데이터 편향에 따른 취약성
결정 트리는 훈련 데이터 내의 클래스 비율에 민감하게 반응합니다. 만약 특정 클래스의 데이터가 압도적으로 많다면, 트리는 불순도를 낮추기 위해 다수 클래스 위주로 가지를 뻗게 되며, 소수 클래스는 무시되기 쉽습니다.

$$ Gini = 1 - \sum_{i=1}^{n} P_i^2 $$

위의 지니 불순도 공식을 보면, 한 클래스의 확률 $P_i$가 매우 크면 불순도가 쉽게 낮아지기 때문에, 모델은 복잡한 패턴을 찾기보다 단순히 다수 클래스로 분류해버리는 '게으른 학습'을 할 위험이 있습니다.

## 3. 코드 예제: 대각선 데이터 분류의 한계

다음 파이썬 코드는 결정 트리가 대각선 데이터를 어떻게 비효율적으로 학습하는지 보여줍니다.

```python
import numpy as np
import matplotlib.pyplot as plt
from sklearn.tree import DecisionTreeClassifier

# 1. 대각선 형태의 데이터 생성
np.random.seed(42)
X = np.random.rand(200, 2)
# x1 > x2 이면 클래스 1, 아니면 0
y = (X[:, 0] > X[:, 1]).astype(int)

# 2. 결정 트리 모델 학습 (깊이 제한 없음)
tree_clf = DecisionTreeClassifier(random_state=42)
tree_clf.fit(X, y)

# 3. 결정 경계 시각화 함수 (개념적 코드)
def plot_decision_boundary(clf, X, y):
    x1s = np.linspace(0, 1, 100)
    x2s = np.linspace(0, 1, 100)
    x1, x2 = np.meshgrid(x1s, x2s)
    X_new = np.c_[x1.ravel(), x2.ravel()]
    y_pred = clf.predict(X_new).reshape(x1.shape)
    
    plt.contourf(x1, x2, y_pred, alpha=0.3, cmap='Wistia')
    plt.scatter(X[:, 0], X[:, 1], c=y, s=20, edgecolor='k')
    plt.xlabel("$x_1$")
    plt.ylabel("$x_2$")
    plt.title("Decision Tree's Diagonal Boundary")

plot_decision_boundary(tree_clf, X, y)
plt.show()
```

**코드 설명:**
- 실제 정답 경계는 매끄러운 $45^\circ$ 대각선입니다.
- 하지만 출력된 그래프를 보면, 결정 트리가 이를 흉내 내기 위해 수많은 '직각의 톱니바퀴' 모양 경계를 만들었음을 확인할 수 있습니다. 이는 전형적인 과적합(Overfitting)의 징후입니다.

---

## 4. 요약
1. **기하학적 제약:** 결정 트리는 축에 수직으로만 데이터를 자를 수 있어, 대각선 형태의 관계를 표현할 때 모델이 과도하게 복잡해집니다.
2. **구조적 불안정성:** 데이터셋에 작은 변화만 생겨도 트리의 루트 노드부터 구조가 크게 바뀌어 예측의 일관성이 떨어집니다.
3. **해결책의 실마리:** 이러한 한계를 극복하기 위해, 데이터를 무작위로 섞거나 다양한 트리를 만들어 평균을 내는 **랜덤 포레스트(Random Forest)**나 **부스팅(Boosting)** 기법이 등장하게 되었습니다.
