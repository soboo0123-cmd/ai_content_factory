## 도입: 우리는 정말 합리적으로 결정할까?

의사결정 이론의 고전적인 관점은 인간을 '경제적 인간(Homo Economicus)'으로 상정합니다. 즉, 모든 정보를 수집하고, 모든 선택지의 확률을 계산하여 자신의 이익을 극대화하는 방향으로 결정을 내린다는 것입니다. 하지만 실제 우리의 삶은 어떤가요? 마트에서 우유 하나를 고를 때 전 성분 함량과 유통기한, 단위당 가격을 모든 제품과 비교하며 한 시간을 보냅니까? 아니면 평소 눈에 익은 브랜드나 가장 앞에 진열된 제품을 집어 드나요?

이번 섹션에서는 컴퓨터 과학과 경제학이 정의하는 **합리적 의사결정**의 정의를 살펴보고, 현실적인 제약 속에서 인간이 선택하는 지름길인 **휴리스틱(Heuristics)**의 원리를 학습합니다. 또한 파이썬 코드를 통해 완벽한 탐색과 휴리스틱 탐색의 효율성 차이를 직접 시뮬레이션해 보겠습니다.

## 1. 합리적 의사결정 (Rational Decision Making)

### 1.1 정의와 전제 조건
합리적 의사결정이란 주어진 자원 내에서 기대 효용(Expected Utility)을 극대화하는 선택 과정을 의미합니다. 수학적으로 표현하면, 선택 가능한 대안의 집합 $A$에서 결과 $O$가 발생할 확률 $P$를 고려하여 다음 식을 최대화하는 과정입니다.

$$E[U] = \sum_{i=1}^{n} P(O_i) \cdot U(O_i)$$

여기서 $U(O_i)$는 결과 $O_i$에 대한 주관적 효용(만족도)을 의미합니다. 이 모델이 작동하기 위해서는 다음과 같은 완벽한 가정이 필요합니다.
1. **완전한 정보:** 모든 대안과 그 결과를 알고 있다.
2. **무한한 계산 능력:** 모든 확률과 효용을 즉각적으로 계산할 수 있다.
3. **일관된 선호:** 선택의 기준이 시간에 따라 변하지 않는다.

### 1.2 알고리즘적 관점: 전수 조사(Brute-force)
컴퓨터 과학에서 합리적 결정은 종종 '최적화 문제'로 귀결됩니다. 모든 경우의 수를 따져보는 전수 조사는 가장 완벽한 합리성을 보장하지만, 데이터가 커질수록 계산 시간이 기하급수적으로 늘어나는 '차원의 저주'에 빠지게 됩니다.

## 2. 제한된 합리성과 휴리스틱 (Bounded Rationality & Heuristics)

### 2.1 제한된 합리성 (Bounded Rationality)
노벨 경제학상 수상자 허버트 사이먼(Herbert Simon)은 인간이 완벽하게 합리적일 수 없다는 **제한된 합리성** 개념을 제시했습니다. 인간은 시간, 정보, 인지 능력의 한계 때문에 최적(Optimal)의 해답보다는 적당히 만족스러운(Satisficing) 해답을 찾는다는 것입니다.

### 2.2 휴리스틱: 마음의 지름길
**휴리스틱(Heuristic)**은 복잡한 문제를 해결하기 위해 사용하는 단순하고 직관적인 판단 규칙을 말합니다. 엄밀한 논리적 추론보다는 경험에 의존하며, 다음과 같은 특징을 가집니다.
- **속도:** 매우 빠르게 결론에 도달합니다.
- **효율:** 적은 정보와 에너지만 사용합니다.
- **오류 가능성:** 논리적 완결성이 부족하여 '편향(Bias)'을 일으킬 수 있습니다.

`[시각화: '완벽한 경로 탐색(미로 전체 탐색)'과 '휴리스틱 경로 탐색(목표 지점 방향으로만 전진)'을 비교하는 애니메이션]`

## 3. 파이썬 실습: 최적해 vs 휴리스틱

이제 간단한 숫자 찾기 게임을 통해 전수 조사(합리적 모델)와 휴리스틱의 성능 차이를 확인해 보겠습니다. 0부터 1,000,000 사이의 임의의 숫자를 찾는 시나리오입니다.

### 3.1 코드 구현

```python
import time
import random

# 1. 환경 설정
target_number = random.randint(0, 1000000)
data_range = range(1000001)

def rational_search(target, data):
    """모든 요소를 하나씩 검사하는 전수 조사 (합리적 모델)"""
    count = 0
    for item in data:
        count += 1
        if item == target:
            return count
    return count

def heuristic_search(target, data):
    """
    이진 탐색(Binary Search)을 휴리스틱의 비유로 사용.
    모든 것을 보지 않고 중간값을 기준으로 범위를 좁혀가는 전략.
    """
    count = 0
    low = 0
    high = len(data) - 1
    
    while low <= high:
        count += 1
        mid = (low + high) // 2
        if data[mid] == target:
            return count
        elif data[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
    return count

# 실행 및 결과 비교
print(f"목표 숫자: {target_number}")

start = time.time()
r_count = rational_search(target_number, data_range)
r_time = time.time() - start
print(f"[전수 조사] 시도 횟수: {r_count}, 소요 시간: {r_time:.6f}초")

start = time.time()
h_count = heuristic_search(target_number, data_range)
h_time = time.time() - start
print(f"[휴리스틱 탐색] 시도 횟수: {h_count}, 소요 시간: {h_time:.6f}초")
```

### 3.2 결과 해석
위 코드에서 `rational_search`는 정답을 찾을 때까지 모든 숫자를 확인합니다. 이는 데이터가 늘어날수록 선형적으로 시간이 증가합니다($O(n)$). 반면, `heuristic_search`로 비유된 이진 탐색은 범위를 절반씩 줄여나가며 매우 빠르게 정답에 도달합니다($O(\log n)$).

인간의 휴리스틱도 이와 유사합니다. 모든 마트의 가격 정보를 수집하는 대신 "대형 마트가 더 쌀 것이다"라는 규칙(휴리스틱)을 적용함으로써 탐색 비용을 획기적으로 줄이는 것입니다.

## 요약

1.  **합리적 의사결정**은 모든 정보를 바탕으로 기대 효용을 극대화하는 것이지만, 현실적으로는 시간과 자원의 제약으로 인해 불가능에 가깝습니다.
2.  **제한된 합리성**은 우리가 가진 인지적 한계를 인정하고, '최적' 대신 '만족'스러운 대안을 찾는 방식을 설명합니다.
3.  **휴리스틱**은 복잡한 문제를 빠르게 해결하기 위한 '직관적 지름길'입니다. 이는 효율적이지만 때로는 편향된 결과를 낳기도 합니다.
4.  파이썬 시뮬레이션을 통해 확인했듯, 전략적인 탐색(휴리스틱)은 전수 조사보다 압도적인 효율성을 제공하며 이는 생존과 의사결정의 핵심 기제입니다.

`[시각화: 데이터 크기(N) 증가에 따른 전수 조사와 휴리스틱의 계산량 증가 곡선 그래프]`
